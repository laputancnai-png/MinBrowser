# MinBrowser 安全与隐私审查（v1.2）

审查日期：2026-11-01 · 审查范围：全部源代码（`src/`）、打包配置、依赖

## 1. 我们防的是谁

| 威胁 | 例子 | 是否防护 |
|---|---|---|
| 恶意或爱追踪的网站 | 第三方 Cookie、追踪脚本、指纹、骗取密码、读取本机信息 | 是 |
| 拿到你数据文件夹的人 | 电脑被偷、备份/网盘泄露、同一台电脑的其他账户 | 是（主密码加密） |
| 网络上的偷看者 | 公共 Wi-Fi、运营商看 DNS | 部分（HTTPS + 加密 DNS；访问的 IP 仍可见） |
| 趁你离开时动你电脑的人 | 浏览器开着、已解锁 | 靠自动锁定（默认 15 分钟） |
| 以你身份运行的恶意软件 | 键盘记录、读内存 | **不在防护范围**：任何浏览器都防不住 |

## 2. 逐项检查结果

| 方面 | 结论 |
|---|---|
| **静态数据加密** | ✅ 浏览记录、收藏夹、密码、网站设置、打开的标签页都用 AES-256-GCM 加密；数据密钥由主密码经 Argon2id（64MB、3 轮）解开；每个数据库用 HKDF 派生独立密钥；快照和日志都绑定了文件名、版本号和序号（防替换、防调换顺序）；崩溃不丢数据（有测试） |
| **密码** | ✅ 每条密码在整库加密之外再单独加密，并绑定网站和用户名，换到别的网站的记录里无法解密；只在完全相同的网站来源上填充；只在 https 和本机地址上自动填充；只填可见、为空的输入框；只在顶层页面工作（嵌入的 iframe 拿不到）；剪贴板 30 秒后自动清除 |
| **进程隔离** | ✅ 所有网页都在沙箱进程里，`contextIsolation` 开、`nodeIntegration` 关、`webSecurity` 开；网页拿不到任何浏览器接口 |
| **浏览器内部接口（IPC）** | ✅ 6 个入口逐一检查发送者：界面命令只接受主窗口；内部页面只能调用自己那一类接口（`min://history` 只能调用 `history.*`）；收藏弹窗、分屏层只接受自己的视图；密码相关消息只接受标签页的顶层页面；所有参数都做类型和长度检查 |
| **内部页面** | ✅ 网页不能跳转到、重定向到、或在 iframe 里嵌入 `min://` 页面；内部页面只用 `textContent` 显示数据（不会被网页标题注入脚本）；所有页面都有严格的内容安全策略（CSP，禁止内联脚本和 `eval`） |
| **网络与追踪** | ✅ 第三方 Cookie 屏蔽；EasyList + EasyPrivacy 拦截；User-Agent 去掉 Electron 标识；加密 DNS（DoH）；关闭了拼写词典下载和 Chromium 自动填充上报；没有遥测、没有崩溃上报 |
| **权限** | ✅ 摄像头、麦克风、定位、通知、屏幕录制等每个网站都要先问你；其余权限一律拒绝；决定只保存到浏览器关闭为止 |
| **文件访问** | ✅ Chrome 导入只能读你电脑上自动找到的浏览器书签，或你在文件对话框里亲自选的文件；网页不能指定任意路径 |
| **打包加固** | ✅ 安装包关闭了 RunAsNode、`NODE_OPTIONS`、`--inspect` 调试入口，开启 Cookie 加密、程序完整性校验、只从校验过的 app.asar 加载；`file://` 额外权限已关闭（浏览器自己的界面改用私有协议 `app://`） |
| **依赖** | ✅ 浏览器运行时没有第三方依赖包（全部打包进程序）；`npm audit` 的 15 个中危问题都在打包工具（electron-builder 及其依赖的 `minimatch` 等）里，不会进入浏览器 |

## 3. 这次审查发现并修好的问题

| # | 问题 | 严重程度 | 修复 |
|---|---|---|---|
| 1 | **开发模式（`npm start`）下 Cookie 明文存储**：Cookie 加密开关只在安装包里打开，开发用的 Electron 没开。Cookie 里是网站登录状态，拿到数据文件夹就能冒用你的登录 | **高** | `npm install` 后自动给开发用的 Electron 打开 Cookie 加密（`scripts/dev-fuses.mjs`）；测试确认 Cookie 文件里已经找不到明文 |
| 2 | **WebRTC 泄露本机局域网 IP**：任何网页都能拿到你电脑的内网地址，常被用来做指纹追踪 | 中 | 只允许使用公网接口（`default_public_interface_only`） |
| 3 | **网站数据文件夹其他用户可读**：`chromium/` 目录权限是 755 | 中 | 改为 700，只有你自己的账户能读 |
| 4 | **锁定期间网页仍能弹权限请求**：弹窗会暴露你开着哪个网站，已允许通知的网站还能发通知 | 中 | 锁定期间拒绝一切权限请求和检查 |
| 5 | **自动填充发送密码前没有再次确认网址**：页面在检测到登录框后立刻跳到别的网站，理论上可能收到密码（需要原网站配合，实际风险低） | 低 | 发送前再次核对标签页当前的网站来源 |
| 6 | **网页可以把内部页面放进 iframe**：拿不到数据，但不应允许 | 低 | 禁止任何子框架加载 `min://` |
| 7 | **`file://` 页面带有额外权限**（Electron 旧行为） | 低 | 安装包关闭该权限；浏览器界面、收藏弹窗、分屏层改走私有协议 `app://` |
| 8 | **意外创建的网页视图缺少默认防护** | 低 | 全局兜底：一律禁止 `<webview>`、默认禁止弹出窗口 |

所有修复都有端到端测试，并在**开发模式**和**加固后的安装包**上各跑了一遍完整测试（76 项全部通过）。

## 4. 已知限制（需要你知道的取舍）

1. **Linux 上 Cookie 加密依赖系统钥匙环**（GNOME Keyring / KWallet）。没有钥匙环的系统，Chromium 会退回到一个固定密钥，相当于只是混淆。浏览记录、收藏夹、密码不受影响，它们始终由主密码加密。
2. **网站自己存的数据（localStorage、IndexedDB 等）不在主密码加密范围内**，只靠文件夹权限保护。想更私密，可在设置里开启“退出时清除 Cookie 和网站数据”（代价是每次都要重新登录）。缓存每次退出都会清除。
3. **回滚无法察觉**：拿到你数据文件夹写权限的人，可以把加密文件换成旧版本（例如恢复你删掉的历史）。他看不到内容，但你也察觉不到被换过。
4. **解锁状态下，“密码”页面可以直接查看密码**，不需要再输入主密码。离开电脑请锁定（⌘/Ctrl+Shift+L），或依赖自动锁定。
5. **解锁期间，密钥和打开的网页都在内存里**；锁定只是隐藏网页，不会关闭标签页，后台的声音会继续播放。JavaScript 的字符串（包括你输入的主密码）无法可靠地从内存中抹掉。
6. **下载默认自动保存到“下载”文件夹**，网页可以不经确认就放一个文件进去（不会自动打开）。设置里可以改为“每次下载前询问”。
7. **加密 DNS 服务商（Quad9 / Cloudflare）能看到你访问的域名**；更新拦截规则会连接 easylist.to。网站本身、你的网络运营商仍能看到你访问的 IP 地址。
8. **macOS 安装包未签名**；浏览器的安全性取决于 Electron/Chromium 是否及时更新，建议每月按 `docs/RELEASING.md` 升级一次。
9. **不能登录 Google 账号**（Google 禁止嵌入式浏览器），决定不做伪装绕过。

## 5. 守护这些结论的测试

- 单元测试 64 个：加密存储（错误密钥、崩溃恢复、日志截断、磁盘无明文）、主密码、密码绑定网站、URL 清洗、分屏几何等
- 端到端测试 86 项（`npm run test:e2e`，开发模式和安装包都跑）：包括“锁定后数据文件里没有任何明文”“网页拿不到内部接口”“内部页面不能互相越权”“网页不能嵌入内部页面”“Cookie 不以明文存储”“网站数据文件夹权限 700”“WebRTC 策略”等
