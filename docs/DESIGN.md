# MinBrowser 设计方案

一个注重隐私的个人浏览器：不收集任何数据，所有浏览记录、收藏夹、密码都加密保存在用户指定的本地文件夹。

## 1. 需求

| 项目 | 决定 |
|---|---|
| 平台 | macOS + Linux |
| 技术 | Electron + TypeScript |
| 浏览记录 | 记录基本浏览轨迹，存到用户指定的文件夹；工具栏有"暂停记录"开关 |
| 收藏夹 | 文件夹分类，可从 Chrome 导入 |
| 密码管理 | 保存、填充（仅完全相同的网站来源）、生成密码 |
| 加密 | 浏览记录、收藏夹、密码全部加密；每次启动输入主密码；忘记主密码则数据作废 |
| 其他 | 多标签页、下载管理、广告和追踪拦截 |
| 不做 | 扩展插件、同步、DRM 视频 |
| 界面 | 顶部横排标签；配色参考 Claude Code 网页版；深色模式跟随系统 |

## 2. 架构

```
┌──────────────────── 主进程（Node，能访问文件和密钥）────────────────────┐
│  VaultService     主密码、密钥派生、锁定/解锁                            │
│  HistoryService   记录浏览轨迹、搜索、删除、导出                         │
│  BookmarkService  收藏夹、Chrome 导入                                    │
│  PasswordService  保存、查询、生成密码                                   │
│  TabManager       创建/切换/关闭标签页                                   │
│  PrivacyGuard     广告拦截、权限控制、DoH、清洗网址追踪参数              │
│  DownloadManager  下载管理                                               │
└──────────────┬───────────────────────────────────┬────────────────────┘
               │ IPC（白名单接口）                    │
┌──────────────▼──────────────┐     ┌──────────────▼───────────────────┐
│ 浏览器界面（渲染进程）         │     │ 网页标签页（每个都是独立沙箱）       │
│ 标签栏、地址栏、各功能面板      │     │ 网页不能调用 Node                  │
└─────────────────────────────┘     │ 表单检测脚本运行在隔离环境          │
                                    └──────────────────────────────────┘
```

安全原则：密钥只存在于主进程，界面和网页都拿不到，只能通过限定的 IPC 接口请求操作。

## 3. 目录结构

```
src/
  main/       主进程（各个 Service）
  preload/    界面与主进程的桥接
  renderer/   浏览器界面
  content/    注入网页的表单检测/填充脚本（隔离环境）
  shared/     类型定义、IPC 约定、纯函数工具
tests/        单元测试 + 端到端测试
```

## 4. 加密设计

数据文件夹内容：

```
vault.meta            盐值、Argon2 参数、被 KEK 加密的数据密钥（单独拿到它也无法解密）
history.db.enc        浏览记录（整库加密快照）
bookmarks.db.enc      收藏夹
passwords.db.enc      密码；每条密码再用独立密钥单独加密，并绑定网站和用户名
sites.db.enc          按网站的设置（停用拦截的网站列表）
session.db.enc        当前打开的标签页，用于崩溃或重启后恢复
<name>.<N>.journal    快照之后的加密写入日志，正常关闭或锁定时合并进快照
config.json           非敏感设置
adblock.bin           编译好的公开拦截规则（不含个人数据）
chromium/             Chromium 会话数据（Cookie、localStorage 等）
```

- 主密码 → Argon2id（64MB 内存、3 轮，用 hash-wasm）→ KEK → 解开随机 256 位 DEK
- HKDF 从 DEK 派生每个数据库各自的密钥

**存储引擎（与最初方案的差异）**：原计划用 SQLCipher，但它是原生模块，需要针对每个
Electron 版本和平台单独编译，开发环境里无法构建和测试。改为使用 Electron 自带的 SQLite
（`node:sqlite`）配合自己的整库加密：

- 解锁后数据库在内存中运行，支持完整 SQL 和 FTS5 全文搜索（trigram，支持中文）
- 磁盘上只有加密文件：一份 AES-256-GCM 加密的快照，加上一份加密的写入日志
- 每次写入都立刻追加到日志，崩溃不会丢失已确认的数据；日志过大、锁定或退出时重写快照
- 快照和每一条日志都用“文件名 + 版本号 + 序号”作为附加认证数据，防止被替换或调换顺序
- 好处：没有原生模块，升级 Electron 和跨平台打包都更简单；磁盘上的保护强度与 SQLCipher 相同
- 闲置 15 分钟自动锁定（可调），锁定时清零内存中的密钥
- 忘记主密码无法恢复；首次设置时要求用户手动输入确认语句
- Chromium 自身数据（Cookie、缓存、localStorage）无法用 SQLCipher 加密：放入数据文件夹，开启 Electron Cookie 加密（系统钥匙串/密钥环），退出时清空缓存，可选"退出时清除所有 Cookie"

## 5. 数据表

```sql
-- history.db
visits(id, url, title, visited_at, duration_ms, transition, referrer_id, tab_id)
visits_fts  -- 标题 + 网址全文索引

-- bookmarks.db
bookmarks(id, parent_id, type['folder'|'link'], title, url, description, position, created_at)

-- passwords.db
credentials(id, origin, username, password_enc, created_at, updated_at, last_used_at)
never_save(origin, created_at)

-- sites.db
adblock_allow(site, created_at)

-- session.db（每次标签页变化约 1 秒后整体覆盖）
session_tabs(position, url, title, active)
```

`password_enc` = nonce + 密文 + 认证标签（AES-256-GCM）。

记录规则：
- 不记录表单数据、页面全文、截图、内部页面
- 网址清洗：去掉 `utm_*`、`fbclid`、`gclid` 等追踪参数
- 暂停记录：工具栏开关，暂停时图标变色，状态重启后保留；暂停期间 Cookie 照常保存，只是不写历史

## 6. 隐私默认设置

- 默认搜索引擎 DuckDuckGo
- 屏蔽第三方 Cookie
- DNS over HTTPS
- 摄像头、麦克风、定位、通知等权限每次询问
- 关闭拼写检查词典的自动下载
- 无遥测、无崩溃上报
- User-Agent 去掉 Electron 和应用名标识，降低指纹唯一性
- 广告和追踪拦截（EasyList + EasyPrivacy）

## 9. 已知取舍

- 不能登录 Google 账号：Google 禁止基于 Electron 等嵌入式框架的浏览器登录（提示“This browser or app may not be secure”）。决定不做伪装绕过，Google 服务改用系统浏览器
- 下载列表只保存在内存里，不写入磁盘（下载过什么本身就是隐私）
- 广告拦截只做网络层拦截，不做隐藏页面元素（cosmetic filtering）
- 首次下载完整拦截规则之前，使用内置的约 30 条常见追踪域名规则
- 分步登录（先输用户名、下一步再输密码）：用户名页只填用户名，绝不在没有密码框的页面填密码；第一步输入的用户名记在当前标签页里（同一网站、15 分钟内），用于第二步选择账号和保存；第一步的用户名没有保存过密码时，第二步不填任何密码
- 自动填充密码只在 https 网站和本机地址上进行，只填可见且为空的输入框，每个页面只填一次；http 网站需点击钥匙按钮。可在设置中关闭
- 打开过的网页内容在锁定期间仍在内存中（页面被隐藏，但标签页没有关闭）
- Linux 上窗口不用系统标题栏（`frame: false`），由界面自己画最小化/最大化/关闭按钮：Electron 38 起在 Wayland 下原生运行，GNOME 不提供服务器端窗口装饰，带系统标题栏的窗口会完全没有按钮。没有改用 X11（XWayland）兼容模式，因为 X11 下其他程序可以监听键盘输入（包括主密码）

## 10. 崩溃恢复

- 打开、关闭、切换标签页或网页跳转后约 1 秒，把所有标签页（网址、标题、当前是哪个）写入加密的 `session.db.enc`；锁定和退出前立即写入
- 写入走加密日志，进程被强制杀掉也不会丢失已写入的内容
- 下次解锁后恢复：当前标签页立即加载，其余标签页第一次点开时才加载
- 恢复出来的网页不算新的访问，不写入浏览记录
- 单个网页进程崩溃时显示“这个网页崩溃了”，刷新即可重新打开；浏览器界面进程崩溃时自动重新加载界面
- 设置中可以关闭；关闭后保存的标签页会被清空
- 暂停记录浏览历史时仍会保存打开的标签页（它会被不断覆盖，不是历史记录）

## 11. 分屏

- 最多两块：左右或上下；分隔条可拖动，每边至少占 20%
- 焦点：哪一边被点击，那一边就是当前标签（地址栏、收藏、密码都跟着它），用橙色边框标出
- 分屏中点击其他标签：替换当前那一边；关闭其中一边：退出分屏
- 开启方式：标签右键菜单；把标签拖出标签栏到网页区域的右边缘（右 30%）或下边缘（下 30%）
- 网页是叠在浏览器界面之上的独立视图，鼠标经过网页时界面可能收不到事件，所以：
  - 分隔条本身是一个盖在两页间隙上的透明视图，按下后扩展到整个网页区域，整个拖动都在它里面完成
  - 拖标签时在网页区域上方显示一个透明的“落点预览层”，同时接收鼠标
  - 这两个层在窗口创建时就加载好，避免拖动开始时还没加载完而丢失鼠标事件
- 分屏状态随打开的标签页一起加密保存，重启后恢复
